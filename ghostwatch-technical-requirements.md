## 3. Technology Stack

| Layer | Technology | Notes |
|---|---|---|
| Foundation model | IBM Granite instruct model (e.g., Granite 4.x) | via watsonx.ai |
| Embeddings | IBM Granite embedding model | for RAG corpus + complaint text |
| Vector store | Milvus (watsonx.ai vector index) or Chroma (local dev) | stores embedded asset + grievance text |
| Agent orchestration | watsonx.ai Agent Lab, or LangGraph as fallback | manages multi-step tool chain |
| Safety layer | Granite Guardian | screens output for unhedged/unsafe claims |
| Backend | Python 3.11+ | agent logic, tool functions |
| Frontend | Streamlit | dashboard, map, drill-down views |
| Mapping | Folium or Streamlit's `st.map` | plots flagged assets by coordinates |
| Data storage (prototype) | CSV/JSON files or SQLite | asset registry, grievance corpus, flag outputs |
| Environment | Python virtual environment; `.env` for watsonx credentials | API keys never hard-coded |

## 4. Data Requirements

### 4.1 Asset Registry Schema

| Field | Type | Example | Required |
|---|---|---|---|
| `asset_id` | string | `SL-2023-114` | Yes |
| `asset_type` | string | `solar_streetlight`, `water_atm`, `ev_charger`, `rainwater_unit` | Yes |
| `location_name` | string | `Ward 7, Market Road` | Yes |
| `latitude` | float | `19.0760` | Yes |
| `longitude` | float | `72.8777` | Yes |
| `install_date` | date | `2023-02-15` | Yes |
| `expected_service_interval_months` | integer | `6` | Yes |
| `warranty_end_date` | date | `2026-02-15` | Yes |
| `contractor_name` | string | `ABC Solar Pvt Ltd` | Yes |
| `last_maintenance_log_date` | date or null | `null` | Yes |

### 4.2 Grievance Corpus Schema

| Field | Type | Example | Required |
|---|---|---|---|
| `complaint_id` | string | `C-4471` | Yes |
| `complaint_text` | string (free text) | `"streetlight near market has been dark for weeks"` | Yes |
| `approx_location` | string or lat/long | `Ward 7` | Yes |
| `date_reported` | date | `2026-08-01` | Yes |
| `category_tag` | string (optional) | `lighting` | No |

### 4.3 Flag Output Schema

| Field | Type | Example |
|---|---|---|
| `asset_id` | string | `SL-2023-114` |
| `confidence_score` | float (0–1) | `0.78` |
| `silence_flag` | boolean | `true` |
| `matched_complaints` | list of complaint_id | `["C-4471", "C-4502"]` |
| `evidence_summary` | string | generated by Granite |
| `recommended_action` | string | `inspect`, `escalate`, `monitor` |
| `output_language_hedge_check` | boolean | must be `true` before display (Guardian-verified) |

## 5. Agent Tool Specifications

### 5.1 `load_asset_registry`
- **Input:** none (reads from data source)
- **Output:** list of asset records
- **Logic:** load and validate schema; flag records missing required fields

### 5.2 `retrieve_signals` (RAG)
- **Input:** asset location, asset type
- **Output:** ranked list of relevant grievance/news text chunks
- **Logic:** embed query (asset location + type) → cosine similarity search against vector store → return top-k (k=5) results above similarity threshold (e.g., 0.65)

### 5.3 `silence_scorer`
- **Input:** asset record
- **Output:** boolean silence flag + months-overdue value
- **Logic:**
  ```
  months_since_install = (today - install_date) in months
  months_since_last_maintenance = (today - last_maintenance_log_date) in months
                                    OR months_since_install if no log exists
  IF months_since_last_maintenance > expected_service_interval_months:
      silence_flag = True
  ```

### 5.4 `cross_reference_classifier`
- **Input:** asset record, retrieved grievance chunks
- **Output:** list of matched complaint IDs with similarity scores
- **Logic:** embedding similarity between complaint text and asset type/location metadata; threshold configurable (default 0.7)

### 5.5 `generate_flag_report`
- **Input:** asset record, silence flag, matched complaints
- **Output:** structured flag report (see 4.3 schema)
- **Logic:** prompt Granite instruct model with retrieved evidence; enforce hedged language via system prompt + Guardian post-check
- **Sample system prompt constraint:** *"Never state that an asset is confirmed broken. Use only hedged language such as 'likely non-functional' or 'probable failure,' and always cite the specific evidence used."*

### 5.6 `escalate`
- **Input:** flag report with confidence_score above threshold (e.g., 0.75)
- **Output:** draft notice text (department/vendor)
- **Logic:** only triggered for high-confidence flags; includes warranty status to determine whether contractor or municipality is liable

## 6. Safety & Guardrail Requirements

| Requirement | Implementation |
|---|---|
| No unhedged failure claims | Granite Guardian screens all `generate_flag_report` outputs before display; reject/regenerate if hedge language missing |
| No fabricated evidence | Flag reports must only cite `matched_complaints` IDs that exist in the retrieval output — no evidence text generated without a source record |
| Fairness check | Silence score computed independently of complaint volume; document this explicitly in evaluation notes |
| No PII exposure | Complaint text is scanned/stripped of names, phone numbers before storage (simple regex filter acceptable for prototype) |

## 7. Dashboard Requirements

| Feature | Description |
|---|---|
| Map view | Plot all assets; color by status (green = active/no flag, yellow = silence flag only, red = silence + complaint match) |
| Flag list | Sortable table: asset ID, type, confidence score, recommended action |
| Evidence drill-down | Click an asset → show full evidence trail (matched complaints, dates, silence calculation) |
| Filter controls | Filter by asset type, ward/location, confidence threshold |
| Escalation view | Separate tab showing drafted escalation notices for high-confidence flags |

---

## 8. Non-Functional / Performance Requirements

- Dashboard should load and render flags for a sample dataset (target: 50–200 assets) in under 5 seconds
- RAG retrieval latency per query: under 3 seconds for prototype scale
- All agent reasoning steps must be logged (for demo transparency) — store as JSON trace per asset evaluation

---

## 9. Development Environment Setup

1. Python 3.11+ virtual environment
2. Install dependencies: `streamlit`, `langchain` (or watsonx SDK), `chromadb` (or Milvus client), `pandas`, `folium`
3. watsonx.ai API credentials stored in `.env` (never committed to version control)
4. Sample datasets placed in `/data/asset_registry.csv` and `/data/grievances.csv`
5. Run agent pipeline as a script first to validate tool chain, then wrap in Streamlit app

## 10. Testing Requirements

| Test type | Description |
|---|---|
| Unit tests | Each tool function (`silence_scorer`, `cross_reference_classifier`, etc.) tested independently with known inputs/outputs |
| Seeded scenario tests | Construct at least 3 "known broken" and 3 "known working" test assets; verify flags match expectations |
| Guardrail tests | Confirm no output ever asserts failure without hedge language |
| Fairness spot-check | Verify a low-complaint-density ward asset still gets flagged correctly on silence alone |
